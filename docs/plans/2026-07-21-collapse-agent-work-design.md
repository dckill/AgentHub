# 自动折叠执行过程设计

## 目标

会话默认以用户消息和智能体最终回复为阅读主线。工具调用、文件更新、中间进度和普通状态事件在本轮完成后收进一条可展开摘要，从而降低长会话的视觉占位，同时保留完整执行证据。

## 已确认交互

- “设置 → 外观 → 显示”提供“自动折叠执行过程”开关，账号同步，默认开启。
- 智能体执行中保持当前轮过程展开；没有最终回复、仍在 thinking、等待权限或等待用户回答时，不自动折叠。
- 最终回复到达且本轮没有待处理交互后，才生成并默认收起执行过程组。
- 已完成历史轮次默认只突出用户消息、执行摘要和最终回复。
- 用户可临时展开或收起任意组；当前页面内的手动选择优先于后续消息刷新。
- 待处理权限、运行中的 `AskUserQuestion`、用户附件及需要用户操作的内容保持可见。

## 摘要与详情

折叠摘要保持单行，展示工具调用总数、唯一修改文件数、错误数和耗时，例如：

```text
8 个工具调用 · 3 个文件 · 1 个错误 · 42 秒
```

窄屏通过单行截断保证不增高卡片；展开后继续使用现有紧凑工具时间线。摘要按钮暴露展开状态，并使用至少 44pt 的点击目标。

## 兼容与边界

- 新设置使用语义字段 `collapseAgentWork`；旧 `groupToolCalls` 字段继续解析和同步，但不再控制这项体验。
- 折叠状态仍只存在于 UI 层；消息协议为 `turn-end` 增加可选兼容字段 `finalTextId`，并在消息元数据中保留可选的 `turnStatus` / `finalTextId`，旧消息缺少这些字段时保持展开，不猜测最终回复。
- 异常中断且没有最终回复的轮次不自动收起，便于检查现场。
- 自动化验收使用分组纯函数测试、设置兼容测试、无障碍/结构边界测试、翻译一致性、类型检查和 production build；不新增截图或浏览器人工验证。
