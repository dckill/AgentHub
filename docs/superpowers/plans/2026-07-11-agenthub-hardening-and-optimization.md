# AgentHub Hardening and Optimization Implementation Plan

> **执行方式：** 默认由主智能体按批次直接选择当前任务所需的具体技能并完成实现、验证和证据复核；不设置通用技能入口，也不要求使用子智能体。自 2026-07-17 起停止新增图形化验证，改为集中实现、TDD 定向门禁和阶段统一自动化回归。步骤使用 checkbox（`- [ ]`）跟踪。

**Goal:** 在不改变自托管、E2EE、移动控制工作台与 Amber Crystal 产品哲学的前提下，完成 2026-07-11 全栈审计中仍属于当前产品范围的实现与本机可执行验证；产品仅支持 Claude Code 与 Codex。

**Architecture:** 以 `agenthub-wire` 作为跨端协议唯一事实源，以账号级生命周期边界隔离 App 明文状态，以经过鉴权的 daemon 控制面和统一 runner shutdown coordinator 保证终态一致性。所有优化均先建立行为/性能基线，再通过小批次 TDD、独立验证和可回滚提交推进。

**Tech Stack:** TypeScript、React 19、Expo Router、React Native/Web、Tauri、Zustand、Socket.IO、Fastify、Prisma、PostgreSQL/PGlite、Redis Streams、Vitest、pnpm 10.11.0、systemd、Docker/Kubernetes。

## Global Constraints

- 永远使用中文记录进度、提交说明和验证结论。
- 全局禁用 `superpowers:using-superpowers`：不得调用、读取或把它作为任何阶段的入口/前置条件；需要技能时按任务直接选择具体适用技能。文档中的历史提及只能表达“已禁用”。
- 不改变自托管、E2EE、移动端远程控制工作台、Amber Crystal 产品哲学。
- 修改 UI 前使用 `frontend-design`；验证使用组件、语义/无障碍、状态机、布局边界和 production build 自动化测试，不再新增浏览器截图、人工点击或其他图形化验收。
- 功能/修复严格执行 RED→GREEN→REFACTOR；不得先改生产代码后补测试。
- 同一批次集中完成必要实现和定向测试，阶段末再运行完整回归；不得为每个小改动重复启动 authenticated Web、浏览器、模拟器或全仓库测试。
- CLI build 前后执行 `AGENTS.md` 规定的 daemon/list/ps/systemd/ss 进程治理。
- 不以跳过测试、放宽类型、关闭安全保护或隐藏错误取得绿灯。
- 每一任务更新 `docs/audits/2026-07-11-hardening-verification-matrix.md`。
- Android 正式 APK 输出到根 `artifacts/`，按规定命名并刷新 latest。
- **2026-07-18 范围覆盖决策：** 当前产品只保留 Claude Code 与 Codex。删除 Gemini、OpenClaw、OpenCode 与通用 ACP 的启动、认证、配置、专用 UI、发布工具和测试；历史会话只允许通用只读兼容，不得恢复创建入口。

- 本机能自动验证的功能使用集中 TDD、定向测试、类型检查和必要构建；因设备、凭据或生产基础设施不可用而无法执行的项目写入用户验收表，不得阻塞其余开发或本地完成判定。
